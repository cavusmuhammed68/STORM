# STORM: Spatio-Temporal Outage Risk Model

**A real-network, graph-attention spatiotemporal digital twin for multi-horizon power-outage early warning in North East England.**

STORM couples a two-layer residual graph-attention encoder with a shared-weight LSTM temporal encoder and a gated static-covariate fusion block to predict power-outage risk jointly at five lead times (1, 3, 6, 12 and 24 hours), for a real twelve-node distribution network spanning Northumberland, Tyne and Wear, County Durham and Teesside. Every dynamic covariate is real and openly sourced (ERA5 reanalysis, National Energy System Operator demand data, and the October 2025 English Indices of Deprivation, IoD2025); the outage-trip label is generated by a fully declared, physically motivated fragility process, since no open UK substation-level outage dataset exists.

## Data

No open UK substation-level outage dataset exists, so STORM's label is synthetic by design (see "Label generation" below). Every **covariate**, however, is real and must be supplied by the user before running either script:

| Folder | Contents | Source |
|---|---|---|
| `weather_hourly_openmeteo/` | One CSV per node (e.g. `Berwick-upon-Tweed_TD15.csv`), hourly, 2014–2023: wind speed, wind gusts, precipitation, temperature, relative humidity, surface pressure, cloud cover | ERA5 reanalysis via the [Open-Meteo Historical Weather API](https://open-meteo.com/) |
| `electricity_system/` | One CSV per year, `demanddata_2014.csv` … `demanddata_2023.csv`, half-hourly national demand and embedded wind/solar generation | [National Energy System Operator (NESO) Historic Demand Data](https://www.neso.energy/data-portal/historic-demand-data) |
| `deprivation/` | `IoD2025_LSOA_NorthEastEngland.csv`: LSOA-level deprivation score/decile and centroid coordinates | English Indices of Deprivation 2025 (IoD2025), Ministry of Housing, Communities & Local Government |

Both scripts locate this folder automatically: place `NE_England_real_data/` anywhere above, below, or beside the script, and `_find_data_root()` will find it (identical search logic in both `storm_pipeline.py` and `repaint_figures.py`).

The twelve real network nodes are Berwick-upon-Tweed, Alnwick, Hexham, Newcastle-upon-Tyne, North Shields, Sunderland, Durham, Consett, Darlington, Middlesbrough, Hartlepool and Redcar.

## Usage

### 1. Full pipeline (data loading, training, all figures and tables)

```bash
python storm_pipeline.py
```

This trains STORM and its three architectural ablations (LSTM-only, GAT-only, GCN-only) plus three classical baselines (logistic regression, random forest, gradient boosting), runs the full statistical evaluation (bootstrap confidence intervals, Holm-Bonferroni-corrected McNemar testing), and writes every table and figure to `results/`. Deep-model training is the slow part of this run.

### 2. Regenerating only the manuscript figures (no retraining)

Once `storm_pipeline.py` has been run at least once (so that `results/tables/eval_artifacts.npz`, `table5_mcnemar_significance.csv`, `table8_spatial_generalisation.csv` and `metrics_summary.json` exist), the manuscript's 12 figures can be redrawn — with different styling, fontsizes, or panel labels — without repeating any deep-learning training:

```bash
python repaint_figures.py
```

This script re-runs only the fast steps (data loading, feature engineering, label generation, windowing — a few seconds) and re-trains only the three classical scikit-learn baselines (also a few seconds), since their per-window test predictions are the one thing not saved to disk by the full pipeline. Every STORM/LSTM-only/GAT-only/GCN-only result is loaded directly from the artefacts already on disk. Output goes to `results/figures_repainted/`, leaving the originals in `results/figures/` untouched.

### 3. Compiling the manuscript

Upload `storm_manuscript.tex`, `sn-bibliography.bib`, `sn-mathphys-num.bst`, and the twelve figure PNGs referenced by `\includegraphics` to the same Overleaf project (or local LaTeX working directory), then compile with pdfLaTeX + BibTeX + pdfLaTeX × 2. No other template files are required; the manuscript is written against the `sn-jnl` class with the `sn-mathphys-num` option.

## Method summary

- **Graph construction**: each node is connected to its $k=3$ real geographically nearest neighbours by great-circle distance.
- **Label generation**: a physically motivated fragility process combines a cubic wind-gust hazard term, a saturating rainfall term, an exponentially weighted temporal smoothing, and an 8-hour-lagged, inverse-square-distance-weighted spatial spillover term across the real network graph, driven entirely by the real ERA5 covariates above. See the `generate_outage_labels()` docstring in `storm_pipeline.py` for the exact equations, and Section 3 of `storm_manuscript.tex` for their full derivation.
- **Architecture**: 2-layer residual graph-attention stack (6 heads) → shared-weight LSTM with a residual skip connection → gated static-covariate fusion → 5-horizon prediction head, trained with a horizon-weighted focal loss.
- **Evaluation**: chronological train (2014–2020) / validation (2021) / test (2022–2023) split; 500-resample bootstrap confidence intervals; Holm-Bonferroni-corrected McNemar significance testing against three ablations and three classical baselines, across all five horizons.
